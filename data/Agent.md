# 数据操作指引

本文件由根 [AGENTS.md](../AGENTS.md) 显式引用；读取／更新数据前先读 [Readme.md](Readme.md)，再读相关包 README 与 manifest。它不替代来源字典或街区验收。

1. 优先复用本仓库快照；需补项时只读检查 `../game-research` 的目录与 manifest，按选区提取所需内容。不得改动上游，也不复制旧项目整体 3D 工程。
2. 每个来源记录源路径／URL、快照与采集日期、SHA-256、许可／署名、CRS／单位／高程基准和缺口；派生包另记筛选／转换规则、源 ID、输出哈希与复现命令。
3. CRS84 经纬度、EPSG:2326 米制 XY、HKPD 高程不能直接混用。保留原始坐标；游戏映射与艺术压缩另存，注明本地原点和高程基准。带 XYZ 的行人网不是地形 DEM。
4. 不因投影交叉或距离近连接天桥、道路、地下层；按楼层和有证据的梯道／升降机连接。未知开放时段、出口归属与人行连通性明确标为待核实。
5. 公交使用完整表而非增量表，保留营办者、线路方向、站序和命名空间；区内站序不等于全程轨迹。港铁出口与站名需配对官方图，不把代表点当作入口或活动生成点。
6. 名称命中、OSM 标签和旧记忆均是线索；核实时间与照片证据分别记录。NPC 身份、卸货日程、雪糕车驻点及活动频率不是 GIS 事实，放入独立设计配置。
7. 重跑脚本前查看写入范围，保护手工资料；新增派生包不要悄悄改写原包 manifest。真实更新需按新源核对差异，不能只更新哈希掩盖不明变更。
8. 文档改动运行 `python3 scripts/validate_docs.py`；数据更新检查对应数量、源 ID、坐标、哈希与覆盖差异，主提取变化按需跑完整验证。历史验证记录保留，新结果注明条件和日期。
9. 交付街区数据按 [完整工作流](../docs/06-production/街区还原工作流.md) 进入实景、资产、Unity 和动线验证；数据校验通过不代表游戏可走。按根 AGENTS.md 提交／推送本次成果。
