# 小步迭代与固定视角省量

工作流 ID：`WF-ITERATE`；版本：1.0；状态：执行规范，成本收益待量测。

## 输入

任务缺陷、现有镜头／路线合同、上一批证据和对应资产清单。

## 步骤

## Agent Token 节约与 HD-2D 画面保真

以下是本项目的执行策略，依据前述生产 SOP 与渲染研究制定；尚无 Token 节省比例的实测。优化目标是减少上下文重复、无效生成和返工，同时通过相同画面验收；模型面数、GPU 耗时与 Agent Token 分开衡量。

1. **按变更读取，交接只留决策**：首次进入任务读取规定入口，后续只查受影响文件／章节及 diff；已读且未变化的资料不重复整篇加载。街区档案保留简短任务记录：资产 ID、来源与配置版本、采用方案、当前缺陷、证据路径、下一步及通过条件。详细日志和失败历史不堆入本文件；来源或环境变化时重新核验。
2. **先锁镜头，按整条路线确定制作范围**：稳定探索方位与平移跟随，让横向主街、纵深支路和前中远景承担构图。按全部允许机位、角色路线及昼夜光照检查可见面；集中制作立面、必要侧面和屋顶。转角、入口、台阶、碰撞、投影及反射需要的体积不能省；远景卡只用于不能接近的层次，不能把整街概念图贴成可行走场景。
3. **先复用，再参数化扩产**：优先检查已有组件、预制体和图集；通用组件按复用清单核查版本与许可。用可重跑脚本批量设置模块、材质和活动锚点，街区差异放配置中，避免逐对象工具操作和逐窗建物体。只重建输入已变化的生成产物，保留 `.meta` 和手工精修；不能为省步骤跳过依赖检查。
4. **用小样锁住像素风格**：先验收白帽主角、一个商铺转角和主街／支路连接，记录实际输出分辨率、角色屏幕高度、各类纹理密度、调色板、像素块形状与足底锚点，再批量复制。清晰轮廓、受控色块和像素纹理必须来自资产；Point 过滤或全屏降采样不能单独代表 HD-2D。过滤、MipMap、抗锯齿按材质与移动画面验证，不统一关闭，也不强制全局 640×360。
5. **生成请求一次说清，局部失败局部修**：imagegen 使用精选实景、布局和已采用风格参考，写清游戏视角、横向／纵深关系、比例、分件、透明需求及用途；角色另注明方向、画布与帧要求。先做少量可导入小样，再生成变体；改招牌或单件不重抽整街。实际检查尺寸、透明边缘、帧切片和文字，不能把生成器承诺当验收结果。
6. **一次解决一个可观察缺陷**：按镜头／走向→体积遮挡→纹理角色→灯光→景深顺序迭代；每轮固定路线、机位和输出条件，只改与缺陷相关的一组参数，保存前后对比。相同思路连续两轮无改善时，先查参考、源码或导入数据，再决定下一步，不继续盲调。达到验收条件即停止无目的参数搜索。
7. **工具返回摘要，完整证据落盘**：批量查询独立状态；日志、构建报告与场景清单保存到约定目录，临时全量输出放 `.local/`。默认只返回成功／失败、首个有效错误、变更对象和证据路径；不向上下文倾倒完整场景 YAML、Base64、工具目录或重复警告。长任务采用适当等待，避免高频空轮询；仍保持进度说明。
8. **分层验证，截图为具体问题服务**：先做相关数据／导入／编译检查，再查看少量固定机位；构图看全景，像素／文字／透明问题看原尺寸局部，动画和闪烁看运动。未变化的截图不重复读取；缩略图不能替代像素验收。集成完成后执行独立 Player 路线与性能验证；纯文档修改只做文档检查，不重建游戏。阶段检查不能替代最终验收。
9. **效果与香港生活均有底线**：保留清晰主角、正确转面与脚步、前中远景遮挡、立体受光和可读街道；Bloom／DOF 最后加入并做开关对照。模块复用仍需用招牌、设施、店面和有目的的活动区分街段，不能用模糊、随机行人或重复立面掩盖缺失内容。
10. **记录成本，验证策略是否有效**：每批在街区实施记录中简记生成次数、返工轮次、主要工具调用及耗时，复用已通过的配置与失败原因。只有工具提供 Token 统计时才报告 Token 数；调用数和耗时仅为代理指标。详细提示词、参数和证据留在主题／街区档案，根入口只维护可复用规则，避免规则本身不断膨胀。

## HD-2D 探索视角与制作省量

- **先分配街道两侧的展示职责**：固定朝向下，镜头正对侧精修店面／入口；靠镜头侧按实际可见范围制作前景檐口、墙面局部、树冠等，并保留必要碰撞／投影／反射代理。过街不会自动展示另一侧店铺正脸；重要商铺若需正面展示，先规划独立镜头区与明确转场，不搬动真实街侧。不能据此断言《八方旅人》没建背面。
- **纵深支路按可见立面制作**：海防道沿街店铺可能在当前镜头里呈斜侧视，不能把它误当无门窗的建筑侧墙。优先转角、门洞、突出招牌、雨篷和可见窗跨；按深入支路及返回的完整路线补齐露出的面，近处保留 3D 深度。
- **扩产前逐栋列可见面清单**：记录主要展示面、转角可见面、前景遮挡面、仅投影／反射代理面、无需制作面，并关联建筑 ID、镜头区、路线机位、资产形式及碰撞职责。取全部允许视角的可见并集，核对遮挡、光照与反射后才能省略；镜头或路线改变时重审。详细判据见 [街道两侧与支路省量](../../docs/03-hd2d/octopath2-composition-study.md#街道两侧与纵深支路的制作取舍)。

- 依据 [八方旅人 II 对照研究](../../docs/03-hd2d/octopath2-composition-study.md)：先锁定允许的探索镜头和主街轴，左右沿街、前后深入支路；固定的是朝向，允许平移跟随。演出旋转镜头不能自动变成探索要求。
- 逻辑根做 3D 移动与碰撞；视觉面片面向镜头，按同一街区轴选前后左右帧，停步回站姿。不靠旋转薄片表达侧身，不把探索限制成横向轨道。
- 按全路线、全部允许机位和灯光的可见面集合安排建模，优先立面、转角回折、屋顶边缘与雨篷；不可见室内和背面延后，参与投影／反射的部分保留代理。近处转角与入口保留体积，远景才用浅模块／卡片。
- 重复窗跨、楼层与墙材模块化，真实店招和辨识轮廓单独制作。省量是减少必须制作的面、方向和独有模块，不声称某个节约百分比或原作内部做法。
- 概念渲染必须有弱透视、横向活动带、纵深连接和真实深度；正交、无烘焙光只适用于贴图生产。景深最后调，不能遮缺面。物理相机拉远时同步检查投影人物大小、阴影距离和景深。
当前场景、资产形态和欠账统一查 [广东道盘点](../../docs/08-blocks/tst-canton-demo/scene-inventory.md)，不把某次对象数／目录版本写成通用步骤。

受影响的小包、前后对比、成本和剩余缺口；改进建议经 [反馈闭环](../00-project/workflow-maintenance.md) 回写其实际所属流程。
