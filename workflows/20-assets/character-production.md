# 像素角色：定稿、多方向与动作生产

工作流 ID：`WF-CHAR`；版本：2.0；状态：从 docs 迁入并整理，完整美术／全街区验收仍待完成。

## 输入

角色设定、实际游戏俯角、尺度／像素合同、所需方向与动作。

## 输出

可编辑源、方向联系表、图集与元数据、预制体和动画实机证据。

## 步骤

调研日期：2026-11-01。本文是《香港像素漫游》的制作方案，不是已完成的角色资产。专业案例、软件能力和本项目试验参数分开记录，出处见 [制作资料索引](../../docs/06-production/hd2d-production-sources.md)。进入制作前先完成 [生产流程的镜头合同](../10-hd2d/hd2d-production-workflow.md)。

## 1. 先统一角色，再画动作

制作两份用途不同的图：**设定转面图**解释正面、背面、左右侧面的身体和服装结构；**游戏视角方向表**按照实际探索镜头的俯角绘制，才是运行时精灵的依据。正交建模三视图不能直接当作游戏里的四向人物。

本项目先定三角白帽、白衣、面部露出范围、身体比例、鞋和衣摆；避免沿用现有概念图偶然添加的蓝发、背包和宽帽檐。正背面共享帽高、肩宽和脚底基准，侧面明确帽尖、脸和衣摆的轮廓。先看黑色剪影，再看灰度，最后上色；在目标屏幕尺寸和明暗背景各检查一次。白衣用有限的暖灰／冷灰表达体积，不能靠纯白色块或过强 Bloom 遮住结构。

八方旅人 II 团队说明，角色是二维像素绘制，背景几乎都是三维；两者协调本身就是制作难题。这支持我们的混合路线，但不提供可照抄的像素尺寸或动画帧数。[Acquire／Square Enix 原访谈](https://www.unrealengine.com/developer-interviews/octopath-traveler-ii-builds-a-bigger-bolder-world-in-its-stunning-hd-2d-style?lang=en-US)

**交付**：角色设定源文件、带方向标签的游戏视角联系表、调色板、禁止自动改变的识别特征、屏幕尺寸预览。imagegen 可以帮助定稿，但多次生成结果必须经过轮廓和像素级一致性修订；不能将互不一致的生成图直接串成动画。

## 2. 方向数由镜头和运动决定

先做正、背、左、右四向的小样，检查主街横移与巷道进出；斜向行走时若换向突兀，再补四个斜向。四向是降低试作成本的项目选择，八向也不是 HD-2D 的统一标准。Gemdrops 的 SO2R 采用不同的移动／待机方向数，说明动作和方向可以独立设计；它属于 Unity 的相近混合画面案例，不冒称八方旅人的原始管线。[Gemdrops 技术访谈前篇](https://cgworld.jp/article/202404-so2r-1.html)

- 标签统一为 `front/back/left/right`，斜向加 `front_left` 等；这里的前后指观察者看到的朝向，另存世界朝向映射，不能把标签当作香港地理南北。
- 运行时从角色世界朝向与相机地面朝向的夹角选择图；镜头旋转时重新映射，停止时保留世界朝向。扇区边界加小范围滞回，防止连续抖图。移动与观看方向不一致的动作以后单独扩展。
- 镜像只用于确认对称的外观和动作；文字、手提袋、单肩包、制服徽章、左右手操作不能直接反转。
- 每个方向用相同画布、缩放、脚底锚点和动作相位。正面完成后尽早做侧面／背面验证，不等整套动画完成才发现衣摆遮脚。

## 3. 静态、待机和步行分别制作

**静态站姿**是每方向一张可用的落地姿势；**待机动画**是站姿上的呼吸、衣摆等循环，不是把走路停在抬腿帧。首个技术样板允许静态待机，生活演出所需的等候、看手机、提袋等另列动作清单。

Animation Mentor 的专业教学先建立接触、下沉、经过、上升等关键姿势，再细化重心和时间；这是通用步态原理，不应把课程中的 3D 帧数直接套成像素游戏标准。[步行循环教学](https://www.animationmentor.com/blog/tutorial-animating-human-walk-cycle/)

本项目推荐执行顺序：

1. 录制或取得可用的步行参考，确定白帽主角的步幅、重心、衣摆响应；只取动作结构，不复制他人角色造型。
2. 在侧向建立两次交替落脚的完整循环：接触 → 下沉／经过 → 抬起／下一次接触。低帧数时可合并中间姿势，不能省去左右脚交替和承重关系。
3. 再画正背与斜向，按同一时间点对齐脚步；帽尖和身体高度变化必须来自动作，不能是生成画布漂移。
4. 用 onion skin 检查跳帧，播放循环检查接缝；通过后再加衣摆和帽尖的次级运动。Aseprite 的时间轴、帧时长与标签可组织这些输出。[动画](https://www.aseprite.org/docs/animation/) · [洋葱皮](https://www.aseprite.org/docs/onion-skinning/)
5. 原地循环交给游戏控制器移动根节点；步频与世界移动速度一起调。可用“速度 ÷ 一周期行进距离”估计循环频率，再用地砖参照检查落脚是否滑动。不要同时烘入角色平移并让控制器重复移动。

**工作量估算例，非定案**：四方向 ×（1 张站姿＋6 张步行）＝28 张；八方向为 56 张，尚不含呼吸、转身、携物、停步和阴影资产。6 帧、源图含帽 48–64 像素都只是第一轮比较输入；先用联系表和实机短循环选择，不宣称是八方旅人的参数。

## 4. 可编辑源 → 图集 → 元数据 → Unity

推荐先保留 `.aseprite` 分层源；动作标签如 `idle_front`、`walk_left`，帧时长在源文件维护。注意 Aseprite 的 tag “Direction” 是顺放／倒放／乒乓播放，与角色四向／八向不是一回事。[标签说明](https://www.aseprite.org/docs/tags/)

导出 PNG RGBA 图集与 JSON，而不是只有一张没有帧信息的大图。以下为根据官方 CLI 写的**待安装后验证的命令模板**，本次没有执行或安装 Aseprite：

```sh
aseprite -b hero.aseprite --list-tags --format json-array \
  --sheet-type rows --sheet-columns 6 --shape-padding 2 --border-padding 2 \
  --sheet hero.png --data hero.json
```

官方支持批处理图集、JSON、标签和留边导出；模板中的列数和 2 像素间距是小样配置，不能保证所有缩小采样都不串色。[Aseprite CLI](https://www.aseprite.org/docs/cli/)

- 先不逐帧裁掉空白，保留共同画布；后续若 trim，导入器必须恢复原画布偏移与脚底位置。足底锚点是本项目补充元数据，不假定 Aseprite 自动提供 Unity pivot。
- 元数据至少记录 `asset_id、canvas_px、foot_anchor_px、directions、clips、frame_rects、duration_ms、world_height_m、source_hash`。像素锚点注明坐标原点，转换到 Unity 时处理上下翻转。
- SpriteRenderer 路线通过切片、pivot、PPU 和动画剪辑导入；MeshRenderer 面片路线通过网格尺寸及 JSON 的 UV 矩形播放，PPU 不会自动控制网格大小。两条路径择一验证，不混用参数解释。
- Point 采样作为角色小样起点，保留 alpha；禁用有损压缩先检查轮廓，再单独比较压缩和缩小策略。导入源不得被 Max Size 静默缩小。Unity 明确区分 Point、Bilinear 等采样；不是开启 Point 就能保证运动中不闪烁。[Unity Sprite 导入](https://docs.unity3d.com/6000.3/Documentation/Manual/texture-type-sprite.html)
- 若运行时只实现简单矩形 UV，禁用图集旋转和不规则紧密裁切；合图留边／扩边要和实际 mip 层级一起检查。脚底 pivot 与包围盒不能随帧变化。

## 5. 3D 辅助出帧是备选生产路径

需要大量服装或复杂携物动作时，可以试验“简模与绑定 → 同一动作在固定俯角、多个方位渲染 → 透明序列 → 像素清理与调色 → 同一图集导入”。它解决转面和动作一致性，但不会自动产生漂亮的像素轮廓；本次未找到足以证明八方旅人普遍使用此法的资料，不能如此宣传。

每次渲染锁定相机、画布、角色高度、光照和时间采样；人物留在同一原点，不把地面与投影烘进角色颜色图。若后续需要动态受光，避免把强单侧阴影固定在颜色贴图里。是否制作匹配的法线／阴影代理，应等夜间侧光测试之后决定。该路径必须用同一镜头对比手绘方案的轮廓、成本和行走效果，不能因为能自动渲染就直接批量生产。

## 6. 角色通过条件

在正式探索镜头下完成双向横走、纵深进出、斜走、停步和转向；没有脚底漂移、帽高跳变、左右特征颠倒、方向抖动和贴图串色。白天、夜间侧光、屋檐阴影下仍可辨认；角色与墙、栏杆、其他角色正确遮挡，投影不会随面片转动消失成细线。灯光、深度和景深的检查顺序见 [镜头与渲染实施](../10-hd2d/camera-lighting.md)。

输出源文件、方向联系表、循环预览、图集与 JSON、导入配置、运行时预制体和实机录像；所有“通过”必须绑定实际版本，不能用概念图替代。

## 验收与回退

按第 6 节执行；方向错误回方向表，脚底漂移回画布／pivot，滑步回动作相位与移动速度，受光或遮挡错误回 WF-LIGHT。未通过循环预览与游戏机位验证不复制到批量 NPC。
