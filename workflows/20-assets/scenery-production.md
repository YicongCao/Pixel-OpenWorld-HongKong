# 香港景物、标识与活动道具制作

工作流 ID：`WF-PROPS`；版本：1.1；状态：广东道交通小样已执行；精确现场版式与美术验收仍待完善。

## 输入

[香港标识参考](../../docs/05-street-life/hong-kong-signage-reference.md)、目标街区资产盘点与实景索引、镜头／尺度合同、允许接近距离、活动需求。当前优先级见 [广东道景物目录](../../docs/08-blocks/tst-canton-demo/scene-inventory.md)。先明确具体类型与位置；本流程的全类型清单不表示所有设施都属于这 30 米。

## 步骤：每类景物共同执行

1. **辨认原物**：记录 asset_id、place_id、实景方向／年代、来源／许可；标识额外记录 exact_text、语言、营办者／品牌、颜色分区、图形、字体依据和安装方式。站牌先核对站 ID、方向和服务线路，不能从红杆猜营办者。
2. **定表现形式与工作量**：全路线列可见面、轮廓、近处视差、投影／反射、碰撞和活动职责。需要轮廓／视差／开合就建几何；文字图案用独立纹理／贴花；远景可裁切卡。记录省略面和适用机位，不默认每件都须完整 3D，也不把卡片当有体积模型。
3. **先做灰模接口**：用米制尺寸和照片比例定体量，未知尺寸标估计。根节点置于地面／墙面安装基准，轮、门、挂点另设 pivot；带锚点的道具先与角色占位和通道试配。复杂轮廓／UV用 Blender，规则几何可用 Unity；复用通过的模块。
4. **按下列类型配方生产**：先一件代表性小样，拆结构、信息面、可动件；纹理以 UV／平面正投影生产，保留可编辑源。imagegen 可生成像素材质或图形草案，最终文字、数字、箭头由可控排版校正，不能直接采用伪字。
5. **材质与导入**：分开颜色、裁切、透明、发光；无必要不增加通道。校验像素密度、纹理边界、缩小采样、法线、UV2及阴影；金属／反光牌不能以过曝白面代替。源与导出分离，保存尺寸／pivot／碰撞、依赖版本、源哈希和 Unity `.meta`，按 [SOP 交接合同](../10-hd2d/hd2d-production-workflow.md#6-资产交接与-agent-可复现要求) 登记。
6. **在实际机位验收**：先无后处理，检查轮廓、内容准确、固定镜头正反路线、主角遮挡和近处视差；再检查阴影／玻璃／Bloom／DOF。文字材质必须通过车身／牌板深度测试，背面字不能穿透；先检查字号与缩放，再验证字体纹理在独立 Player 重载后正常。标识看“真实版式”和“游戏距离可识别”两层；看不清时先调整像素排版／贴图尺寸／构图，不无依据把牌放大数倍。
7. **装配交接**：通过后做预制体或明确模块组，带放置基准、collision_role、活动锚点和允许机位。调用 [WF-SCENE](../10-hd2d/scene-assembly-validation.md) 摆放和运行，不在单件流程里宣布全场景完成。收到反馈按 WF-MAINTAIN 更新对应类型配方与验收项。

## 类型配方

### A · 商标、店招、门牌、广告

核对官方图形及该地址实景 → 分招牌框／底板／固定件和独立标识面 → 用可靠源图或校正后的图形制透明纹理 → 按照片排字与安装 → 分开发光图形和实际照明 → 验证店门关系、昼夜可读与缩小轮廓。Apple／莎莎已有图形面片与几何框架；在固定机位下轮廓成立就无需强做实体雕刻。近景突出字有可见侧厚／投影时再做挤出几何。品牌来源与代码许可分开。

### B · 街名牌、交通牌、导向牌

先分类街名牌／交通指示牌／商业导向牌 → 用现场照片与对应路政署／运输署图纸选样式 → 校对繁体／英文、楼号范围／箭头（仅原牌具有时）→ 依真实比例排版，记录字体来源或缺口 → 建牌板厚度、边框、抱箍和立柱／壁挂 → 安装面朝道路正确方向 → 正向与返回路线检查。不能把当前绿色矩形当香港街名牌标准，不能拿“所有路牌一种颜色／字体”做模板；准确色值和字形需对应具体牌型证据。

### C · 公交／小巴站牌与候车设施

核对营办者、站 ID、方向、年代和线路 → 取得正面信息面及侧背安装参考 → 拆顶牌、线路牌／时刻信息面、立柱、底座与固定件 → 按该站真实版式分层排字 → 如现场有候车亭／座椅／显示屏，再做对应模块 → 配置站位、排队锚点、上下客口和车辆停靠基准。先交叉核对车辆线路与站牌营办者／站 ID：途经不等于停站，不匹配时只驶过，不能沿用占位上下客逻辑。文字信息与几何分开更新；只在来源支持时添加二维码／屏幕，不给所有站强加同一配置。先以 DEMO 站位保留编排标签，实地站位确认后才能称真实还原。资产验收检查牌面，运营验收由 WF-SCENE 检查车门、人流和路线共用状态。

### D · 栏杆、路桩、路灯、垃圾桶与街道设备

按街段照片确定型号／色带／间距 → 模块化立柱、横杆、连接、灯头或桶盖开口 → 做少量变体和受控旧化 → 按可接近程度选几何或卡片 → 配简化碰撞与基准。垃圾桶近处能绕行时应补体积和背侧；灯杆、发光灯罩和真正 Light 分别交接。消防栓、配电箱、电话箱、咪表只在位置核实时制作，不为了“港味”任意填充。栏杆必须留门口／上下客开口。

### E · 地面、路缘、排水、井盖、盲道与标线

先确定高程、材质和通行职责 → 路面平铺材质，标线／污渍用独立贴花，路缘／井盖高差与沟槽按可见需要做浅几何 → 校对接缝、排水方向、标线样式与盲道连贯性 → 设置防 z-fighting 的间距 → 足底、轮胎、斜视与像素缩小时测试。不能以零散装饰盲道代替真实无障碍连接；无依据不新增过街设施。

### F · 建筑附属物与橱窗小物

外墙空调、支架、排水管、电线槽、雨篷、卷闸、灯箱：从真实立面确定位置和重复节奏 → 分主轮廓和薄细节 → 复用小模块并保留转角接口 → 校验墙面挂靠、阴影和远处闪烁。橱窗柜台、商品、屏幕：先定玻璃后可见深度 → 前排轮廓做简模、后排允许纹理卡 → 玻璃内外分别检查透视、反射与遮挡。建筑结构调用 [WF-BUILDING](building-production.md)，不重复做整栋楼。

### G · 树木、灌木、花盆与前景遮挡

按地点辨认体量和冠形 → 树干／树池／花盆保留需要的体积 → 叶簇用有限交叉裁切面或简模 → 控制透明留边、深度与投影 → 沿全路线检查侧面暴露和角色被遮时间。前景卡限定适用机位，不能堵住转弯入口；风摆是后续可选功能，要配合深度／阴影通道验证。

### H · 巴士、货车、雪糕车及搬运道具

车辆先核对该地点／年代车型与用途、营运区域 → 定车身比例、轮距、车门／窗口位置 → 拆车身、轮、门、标识与必要可见内饰 → 做车轮／车门枢轴和简化碰撞 → 绑定停靠／转弯路线试姿态。资产库与场景投放分开：有三色的士资产不代表可在同一街段出现；记录允许区域，在场景验证中断言实际投放。左行环境不等于车门任意一侧都能上客。货箱／推车先确定抓握、放置、轮子和货物层次，再与 [角色动作](character-production.md) 同步做携带／推／放下姿势；循环需要完整开始／结束。富豪雪糕车须有时段／驻点依据或标明设计编排，不能用品牌出现推定固定位置。

## 输出

每件：可编辑源、模型／卡片／贴花及明确表示形式、纹理与最终排字、Prefab／模块组、碰撞与活动锚点、导入合同、原物证据与实机检查图。更新资产目录的“占位／已制作待精修／已验证／缺失／候选”状态，不使用模糊的统一“完成”。

## 验收与回退

身份和位置有依据、版式／色彩／文字正确、比例和可见面成立、遮挡／深度／活动接口正常，才允许同类扩产。参考不足回步骤 1；风格或视差失败回步骤 2–4；透明／发光失败回步骤 5；通道／排队问题回装配流程。纯贴图适合目标机位时可通过，不以建模面数作为精致度指标。
