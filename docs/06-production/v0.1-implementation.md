# v0.1 实施规划：一条会生活的香港街道

2026-11-01 · 首个可玩版本计划 r1 · 状态：已进入 V1-00 环境验证；V1-01 选段及后续街区实施尚未开始。

**首版交付是一段可反复行走、可停留观察、有真实香港依据的 HD-2D 小街区，以及能重新构建它的资产与工程。** 玩家可控制白帽小巫师横向走过主街、深入支路、观察站口和公交活动、保存退出再继续。目标是一次约 5–10 分钟的探索与观察体验；这是设计目标，不是靠放慢速度或强制等待拉长内容。

它同时验证三件事：画面是否达到目标、街道是否自然可走、数据到实机的制作方式是否能复用。技术灰盒是中途检查点，不作为最终 v0.1 发布结果。远期扩展见 [Roadmap](roadmap.md)。

## 1. 选段与范围冻结

首选仍从广东道—海防道相关街段核对。**第一项工作是比较具体边界，而不是马上把现有概念图做成场景。** 现有资料尚未证明原来的 80–150 米主街＋30–60 米支路范围能同时容纳真实巴士站、港铁口及完整通行路线。

- 候选 A：广东道—海防道街角，以连续商业立面和横向主街为重点。
- 候选 B：海防道另一端与弥敦道相关街段，以站口及交通活动的可达性为核对重点；是否合适须按实际站位、过街和街景证据确认。
- 选择标准依次为：真实连续步行路线、可读的横向／纵深空间、可核实的港铁口与巴士停靠点、参考图片覆盖、独有资产制作量。此处是候选比较，不是已核验的具体出口或班次推荐。

在 V1-01 形成唯一 `block_id` 和边界：精做核心为一个街角＋一条纵深支路，最多增加一个有真实连接的必要短段；首版最多两个可走场景单元。视野外楼体作为背景，不计可玩面积。

如果这个范围仍无法同时满足所需交通节点，应重新选段并说明取舍，不能把站口／站牌搬到商场旁，也不能默默把首版扩成整个尖沙咀。无真实依据的坡道／天桥测试件留在独立开发场景，不进入正式街区。

## 2. 首版功能合同

| 范畴 | v0.1 必须交付 | 本版边界 |
| --- | --- | --- |

| 地理空间 | 连续主街、纵深连接、正确街侧／路口、真实可走路径及明确边界 | 不要求整个海防道、整片商场或研究窗口全部开放 |
| 画面 | 像素白帽角色、统一像素纹理的立体建筑、前中远景、受光与接触阴影、稳定遮挡和克制景深 | 不以写实背景贴像素角色代替；不要求光追、自由旋转相机 |
| 城市识别 | 核实的建筑／商铺、双语路牌、栏杆／路缘、站牌与港铁出口标识 | 只使用本街段真实存在的品牌；不要求 Apple、7-Eleven、麦当劳全部同场 |
| 行人 | 有起终点的走动、等灯／停留／候车、正确站口进出、基本避让 | 小范围状态机和路径；不模拟全城常住人口 |
| 车辆与公交 | 局部车辆行驶；一辆巴士完成靠站、开门、上下客、队列变化与离站 | 经核对的局部路线；NPC 可上车，玩家不能乘车或驾驶 |
| 微活动 | 一组非交通的完整活动，优先卸货收货；若场所不支持则选择有证据的取餐／补货等 | 不同时实现全部 16 类活动；活动与道具、声音必须同步 |
| 声音与时间 | 一套可游玩的时段／天气预设；路口、车辆、脚步与活动的空间声音；另有昼夜与晴雨对照验证预设 | 对照预设用于验证受光和行为差异，不承诺连续天气与完整城市时钟 |
| 工程交付 | 可运行 Unity 工程、本机架构的 Mac Player、依赖版本、重建说明和验证记录 | 不以编辑器 Play 模式替代独立构建；Windows 后续再评估 |

首版可选项包括拍照模式、迷你地图、更多角色方向动画、第二种非交通活动、连续时钟和无缝加载。只有必需项通过后才做，不用它们掩盖通行、风格或生活活动缺陷。富豪雪糕和休息日群体保留为后续高辨识内容；如果选段恰好有充分证据且能复用已有资产，再评估加入，不能强行塞入。

## 3. 技术与制作策略

沿用 [引擎研究](../04-engineering/engine-selection.md) 的 Unity 3D／URP 候选方向。先核实本机版本、现有授权和框架兼容，再锁定一套控制器、一套输入责任和一套镜头责任。没有框架授权时先做可替换的最小白盒验证；这不等于正式决定手写全部通用系统，也不因规划而自动采购。

先完成“能走的灰盒”，再用真实街景＋布局引导图生成同机位概念，随后验证一栋商铺的生产资产。这样能在批量生成前发现相机看不见入口、双侧建筑遮挡或纵深太窄的问题。imagegen 输出、手工修订和生产采用版本分别管理，提示词与输入参考必须归档。

初始制作量只用于发现成本，不能作为任意修改地理的配额：约 4–6 个可复用立面／转角模块、1–2 个独有识别界面、1 套路面／路缘／标线、约 12 类基础街道道具、1 套主角动画、少量 NPC 外观与行为动作、2 类小车表现、1 辆巴士及所选活动需要的道具。港铁口、巴士站和实际铺面以核实清单为准；新增独有项必须记录成本。

基础路面和规则墙体先使用 Unity 模块；需要复杂轮廓、阶梯／站口、车辆或专用 UV 时再用 Blender。不要把所有物件都走一次复杂建模链，也不能用一张整街贴图替代可行走的场景。

## 5. 依赖顺序与检查节点

执行顺序：V1-00／01 → V1-02 → V1-03 → V1-04；活动逻辑在 V1-02 后开始验证，待 V1-04 完成后合入 V1-05；之后 V1-06 → V1-07。

| 节点 | 可审阅成果 | 决策 |
| --- | --- | --- |
| G0：范围成立 | 最终边界、实际街景、交通节点、可走路线与缺口 | 选段成立才锁范围；不成立先换边界，不搬设施 |
| G1：技术能跑 | 主角走完灰盒，Agent 修改到构建的过程可重复 | 锁控制器与镜头基本方向；核心适配受阻则先处理技术选择 |
| G2：画面能成立 | 同机位概念与一栋实机商铺、角色、光照对照 | 主观方向确认后锁像素／材质规范；依据实际制作工时更新剩余排期 |
| G3：街道在生活 | 主角试走完整街段，公交／站口／非交通活动可观察 | 查通行、行为始末、视听同步；不以只摆道具过关 |
| G4：首版可交付 | 独立 Player、固定路线与性能记录、剩余问题单 | 必需项通过才标记 v0.1 候选；不是完成文档就发布版本 |

节点是验证点，不新增逐步人工许可流程。Agent 在已授权范围内持续推进可独立完成的工作；涉及用户主观画面反馈、付费采购或关键范围冲突时，清楚指出待决定的具体内容。

## 6. 主角验证动线

V1-01 核定实际位置后，以同一份路线配置驱动重复验证；以下 A–F 是功能锚点，不是未经核实的现实地点。

1. A：从可识别的街口开始，沿横向主街走到 B，经过玻璃／招牌受光区及近景雨篷，检查人物深度、脚底和遮挡。
2. B → C：走入真实纵深连接，遇到有人停留或搬运的局部空间，验证绕行和镜头方向；有已开放的真实台阶时走一遍。
3. C → D：到核实的港铁口附近，观察人流由入口进入人行网络，确认角色不会从墙中出现或堵在梯口。
4. D → E：通过正确过街位置走向巴士站，观察车辆停稳、车门、上下客和队列变化；玩家只能步行经过。
5. E → F：观察所选非交通微活动的完整过程，停留两分钟后按同一路线返回 A。
6. 在 B、D 和 F 分别保存／退出／继续；再在镜头区或场景边界往返 20 次，检查方向、楼层和对象归属。

具体路线可能调整为相反顺序，但所有功能锚点和真实连通关系必须保留。独立阶梯／天桥测试场景的通过记录另存，不能把测试件截图当作正式街区。

## 7. 首版验收与可测负载

沿用 [通用验收](../07-validation/acceptance.md)，本版补充以下固定条件；全部为目标而非已测结果。

- **基本功能**：键盘操作、暂停／继续、设置与存档可重复使用；路径不穿墙、不坠落、不陷入不可恢复卡死；镜头切换不反转持续输入。
- **风格**：同机位比较真实参考、概念与实机；主街横向、支路纵深、建筑体积与像素人物成立。生成伪字、异常尺度和明显写实／像素混搭必须修正；用户主观认可单独记录。
- **交通与生活**：重复观察至少 3 次公交循环与 3 次所选微活动；站口进出有合理生成／退出边界；不存在车门没开人已上车、货物无去向、队列永不释放等问题。调试频率是测试配置，不是现实班次。
- **配置基线**：正常测试档以 12 名可见 NPC（包含候车、站口和活动演员，不含主角）、2 辆行驶小车、1 辆活动用货车和 1 辆巴士为初始负载；货车仅在选择装卸时出现。繁忙档比较 24 名 NPC、4 辆小车及同等活动车辆。具体点位容纳不下时调整出现时序，记录实际峰值，不把密度目标凌驾于地理。
- **性能**：在当前开发 Mac 的独立 Player、1080p、已记录质量设置下运行至少 10 分钟；暖机后帧时 P95 ≤16.7 ms、P99 ≤25 ms，常态移动不出现 >50 ms 的明显停顿。繁忙档记录差异，不假称同样达标；720p／1440p 与非整数窗口检查像素、文字与画面稳定性。
- **内存与状态**：比较第 2–5 分钟和第 7–10 分钟同一路线的内存与对象数；重复进入／退出后不持续累积。位置／楼层与活动恢复不能生成重复人车。
- **情境对照**：白天／夜晚检查受光与景深；晴雨及工作日／休息日验证预设至少改变一项合理的行为或停留安排。它们不需要同时形成完整连续日历系统。

若正常档无法达标，先记录瓶颈并优化阴影、透明层、活动更新和可见范围；不要悄悄关掉全部人群或降低分辨率后仍引用原条件的性能结论。影响地理、可走性、核心风格、状态恢复或必需活动的缺陷属于阻断项；新增装饰不能抵消它们。

## 9. 排期、收敛与下一步

当前不列未经测速的完成日期。先排 V1-00、01、02，分别得到环境闭环、可核实选段和可行走灰盒；在 G2 的首栋商铺与角色完成后，按真实工时、剩余资产数量和集成缺口给出首版的滚动日期估计。已有的 8–17 人日旧估算不沿用。

**当前先执行 V1-00，下一阶段核实 V1-01 选段。** 环境验证不自动开始未核实街段或采购框架；实施范围沿用用户具体任务。v0.1 通过后进入相邻第二街段，以复用成本验证是否具备扩区条件。
