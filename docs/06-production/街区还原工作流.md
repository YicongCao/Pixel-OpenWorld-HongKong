# 香港 HD-2D 街区还原工作流

本文件维护街区制作流程，由根目录 [AGENTS.md](../../AGENTS.md) 引用；常驻项目约定与提交／推送规则统一在该入口维护。用户要求还原一个香港街区时，执行下面的完整链路；仅研究、仅修图或局部修复的请求按指定范围执行。沿用已有授权，例行可逆操作不反复确认。不要把本文件理解为现在就开始制作未指定的街区。

文中的代码路径均相对于仓库根目录；`../game-research` 指仓库的同级工程，不相对于本文件所在目录。

## 项目目标与固定边界

- 制作以《八方旅人》为参照的 HD-2D 香港步行世界：像素角色、像素纹理的立体街景、横向主街、纵深巷道、真实遮挡、克制的景深与光照。主角是三角白帽、白衣小巫师。
- 核心体验是沉浸式香港街道生活。地标、普通建筑、交通设施、人群、劳动活动、声景、时间与天气共同验收；不以空建筑和随机行人替代城市生活。
- 首版无剧情、战斗或玩家可乘交通。汽车行驶、公交靠站、NPC 上下车和站口进出属于环境模拟，不自动扩展为玩家驾驶、乘车或完整站内空间。
- 当前实现目标为 Unity 3D 空间与 URP 3D 渲染路径；框架、包版本及性能仍须验证。参考 `docs/01-vision/vision.md`、`docs/03-hd2d/street-camera.md` 和 `docs/05-street-life/street-life.md`。
- 保留真实街道方位、路口顺序、建筑街侧、海陆关系和通行楼层。镜头方向与地理方向分开；不可为了构图搬动真实地标或虚构连接，不把整个尖沙咀夸张成山坡。

## 0. 开始任务与确定交付范围

1. 读取本文件、`AGENTS.md`、`docs/README.md`、`docs/Agent.md` 与 `docs/Skill.md`，涉及数据先读 [data/Readme.md](../../data/Readme.md) 与 [data/Agent.md](../../data/Agent.md)，涉及资产先读 [assets/Readme.md](../../assets/Readme.md) 与 [assets/Agent.md](../../assets/Agent.md)；再按任务读取对应主题、目标街区已有资料与未完成记录，检查 Git 状态和远程。复用现有工作，不从零重复采集。
2. 将用户地名落成稳定 `block_id`、地理边界、目标街段、出入口和一条玩家验证路线。区分本次可走区、仅可见背景、后续扩展区；边界未指定时先选择可独立验证的小街段并说明假设。
3. 明确视角、主要街道方向、参考年代、时段／天气和本次必须出现的生活活动。只有缺失信息会改变关键地理或交付范围时才询问；其余取可撤回的初值推进。
4. 在 `docs/08-blocks/<block_id>/plan.md` 记录本次范围、步骤、依赖、验收与缺口。后续每阶段更新实际状态，不能把计划标为完成。

## 1. 从 game-research 建立逻辑骨架

1. 只读检查相邻 `../game-research` 的香港数据目录、目录索引、README 和 manifest；本项目先读 `data/hong-kong/README.md`。优先复用本仓库已有对应快照，仅追加所需缺项与更新。
2. 按选区和必要缓冲提取道路、建筑脚印、POI、地形／高程依据、三维行人路径、公交／小巴站点与线路、港铁站点／出入口／街道图／布局图，以及相关城建设施资料。拷贝所需原件或可追溯派生数据到 `data/blocks/<block_id>/`，不让运行时依赖相邻仓库。
3. 每个来源记录来源仓库相对路径、发布者／原始 URL、快照及采集日期、SHA-256、许可／署名说明、CRS／单位／高程基准、筛选规则及覆盖缺口；派生结果另有输出哈希与复现命令。现有公共数据可按源 ID 引用，不为每街区重复复制完整大包。
4. 公交使用完整表，不把增量表当全量；保留营办者、线路方向、站序和站位。区内截取站序不等于完整线路，也不是车辆实际行驶轨迹。必要时保留区外相邻站作上下文，明确截断位置。
5. 经纬度、EPSG:2326 米制与 HKPD 高程分开；三维行人路径不是地形 DEM。楼梯、扶梯、桥、隧道、升降机保留 `level_id` 和有证据的连接；不能因平面相交或距离近就自动互通。
6. 生成带北箭头、比例与来源的逻辑骨架图：可走区域、建筑脚印、道路／车道候选、路口、交通站位、跨层通道、地标及服务门候选。人工核对真正可通行关系后，另存游戏布局与压缩说明。

完成条件：数据能追溯，逻辑骨架能够解释主角从哪里走到哪里、车辆在哪里运行、人群从哪里出现或离开；未知位置明确标为待核实，不用生成图补地理事实。

## 2. 在线采集与核对真实街景

1. 查询目标街区的实际街景、官方设施／运营商图片、公开可访问的街道照片及必要的历史资料。地图和运营商官网核对身份、地址、出口和站位，照片核对立面、街道家具、视线与生活细节。
2. 参考至少覆盖本次关键位置：主街双侧立面、连接巷口、街角转折、重要高差，以及涉及的公交站／地铁口；有资料缺口就缩小或标记该部分，不拿其他街区图片冒充现场。
3. 实际查看图片，记录可确定的位置、朝向、拍摄／发布年代和可信度。区分同名地点、同一建筑不同立面、历史照片与当前状态；不将搜索缩略图标题当成位置证明。
4. 在 `references/blocks/<block_id>/index.json` 记录原网页 URL、原图 URL（可得时）、作者／发布者、日期、位置／方向、用途、许可或再分发状态、文件哈希及对应 `source_id/place_id`。
5. 可保存且可入库的参考原件放同目录。仅能查看或不宜再分发的图片保留链接和观察记录，不将受限原件提交远程；临时文件放被忽略的 `.local/`。遵守来源访问条件，不绕过登录／下载限制。
6. 用照片修正“待核实”的资产与活动候选，注明证据；不以主观印象覆盖原地图。人群身份、日程、卸货频率和雪糕车驻点不是 GIS 自动提供的数据。

完成条件：每个关键视觉锚点能对应实际街景；参考图与逻辑骨架之间的冲突、年代差异和遮挡缺口有记录。

## 3. 用实际参考图生成 HD-2D 概念图

1. 制作一张简化布局／镜头引导图，标注主街、支路、建筑街侧、高差、相机方向、近中远景和主角路线。必要时先用简单灰盒检查视线，避免要求图像模型从复杂地图自行推理全部几何。
2. 调用 imagegen 前读取其技能和当前工具说明，实际查看准备输入的参考图片。使用工具支持的参考图参数传入真实街景及布局图；不能只写“参考某街景”就声称完成图生图。无法传入必要参考时，记录缺口，不把纯文生图标成基于照片的还原。
3. 明确哪些输入负责地理布局，哪些负责建筑外观，哪些负责风格；构图只在已核对骨架内调整。先生成与目标日常游戏镜头一致的一幅，再按需要探索同机位昼夜／天气变体。
4. 提示词必须包含下面的要素，按实际街区替换，不把所有香港元素硬塞进一图：

```text
任务：把参考图中的 [真实街区/街段] 转化为用于 Unity 制作的 HD-2D 游戏场景概念。
依据：布局图控制道路、建筑街侧、路口顺序与高差；街景图 A/B/C 控制指定立面、店铺与交通设施。保留这些约束，不移动或新增地标来改善构图。
视角：接近《八方旅人》的日常探索镜头；固定低斜俯视、弱透视，俯角以约 25–35°为起点；非垂直 TopDown，非街景人眼摄影。镜头从 [方向] 看向 [方向]，主街在屏幕中主要横向延伸。
空间：主街有可走宽度；[实际巷道/连接路] 向纵深延伸；呈现可读的街角、侧墙、雨篷、前后建筑重叠和有依据的台阶／平台。前景遮挡、中景可走区、远景天际线层次清楚。
美术：清晰的像素人物，像素纹理的简化立体建筑与道具，统一颗粒和材质语言；不做写实背景贴几个像素人物，不用整幅模糊掩盖细节。
光照与景深：真实体积受光、接触阴影、克制的光晕；主角及主要行走区清楚，近远景适度虚化，纵深通路仍可辨认。
角色与生活：三角白帽白衣小巫师，脚底与尺度清晰；按街段证据布置 [候车/卸货/站口出入/停留等]，留出主角路线。车辆按香港道路方向运行。
标识：使用已核实的商铺、港铁出口和站牌位置；重要繁体中文／英文标识预留独立排字区域，生成文字不是最终生产文字。
用途：构图、模块拆分和灯光参考；不是实机截图，不据此推导隐藏几何或真实坐标。
```

5. 生成图保存到 `assets/blocks/<block_id>/generated/concepts/`，附完整提示词、输入参考清单／哈希、工具、输出哈希和已知偏差。先检查镜头是否像 HD-2D、道路是否正确、前后层次是否可走、材质是否过度写实。
6. 若模型改变路口或楼层，修正引导图／提示词并迭代，不反过来修改真实骨架迁就错误图。概念未达到空间要求时，不进入批量贴图制作。

## 4. 将概念拆成可实现的资产包

1. 建立资产清单，区分复用模块与街区独有物件：地面、路缘、标线、墙面、窗格、建筑转角、雨篷、招牌、公交／汽车、站牌、地铁口、栏杆、树木、道具及人物。
2. 根据逻辑尺寸、目标镜头和概念生成纹理／图集／精灵；明确像素密度、物理尺寸、正交展开、可平铺边界、透明背景、留边与图集布局。贴图避免烘入不一致的镜头透视；动态受光资产避免画死与场景矛盾的强阴影。
3. 颜色、发光、透明裁切等需要的通道分别制作和验证；法线、深度、粗糙度不是从一张概念图自动得到的可靠真值。先验收一个商铺与一种地面，再扩展同类资产。
4. 店名、街名、出口号和路线文字单独排版，替换生成伪字。角色和 NPC 动画检查朝向、足底锚点、帧间体积；车辆检查尺度、朝向及车门位置。
5. 生成资产放 `generated/`，手工修订放 `authored/`，通过资产清单明确最终采用版本。重建脚本不得覆盖 `authored/`，不得把整幅概念图切层当作完整可行走世界。

完成条件：资产能按清单对应地面、立面、遮挡、灯光和碰撞职责；纹理导入预览正确，不宣称概念图已经是游戏资源。

## 5. 按需建模并导入 Unity

1. 先用 Unity 基础几何和现有模块搭建逻辑骨架；规则路面、简单墙体和碰撞不必绕行 Blender。需要独特地标轮廓、复杂转角、台阶、站口、桥体、车辆或 UV／烘焙时使用 Blender。
2. Blender 产物保持明确米制尺寸、局部原点、轴向与枢轴；建筑分拆底座、立面、侧面、屋顶／雨篷、招牌和灯具。隐藏侧面按镜头需求补齐，不逐栋恢复不可见的完整内部。
3. 保存可编辑源文件，并导出当前 Unity 工程实际支持的格式，记录导出设置；不要假设任意模型格式无需导入器即可使用。核对比例、朝向、UV、法线、材质和碰撞，避免原始巨大 GIS 坐标直接进入引擎。
4. Unity 工程目录未确定时只建立一套明确的工程结构；锁定 Editor／URP／框架／包版本，保留 `Assets`、`.meta`、`Packages`、`ProjectSettings`，不提交 Library 等缓存。使用现有兼容组件，不并行堆叠输入／角色／镜头控制器。
5. 游戏世界采用 X=东、Z=北、Y=高度的明确映射，来源数据不变；真实高度与艺术压缩分别记录。使用 3D 碰撞与有证据的跨层连接，不用全局 Y-sort 代替楼层。
6. 配置区内稳定镜头、纵深跟随与必要镜头区过渡；像素角色使用逻辑根节点＋直立视觉子节点，验证受光、深度写入、裁切和稳定阴影。近景屋檐／树冠采用局部遮挡处理，景深保持主角与可走区清楚。

完成条件：场景在 Unity 内能运行，导入无关键错误，主角可沿骨架行走；仅模型导入成功不算街区完成。

## 6. 添加香港街道活动

- 行人：有目的地的行走、等灯、候车、排队与停留；按世界位置和楼层寻路，入口／出口有合理边界，不能从墙里生成。近处完整行为，远处简化。
- 汽车：按核实的道路方向、车道、信号和停靠空间运行，转弯不穿建筑、过街不撞人；真实车道资料不足时采用明确标注的局部编排路线，不伪称完整交通还原。
- 公交与站点：按已核对车型／站位组织驶入、减速停靠、开门、下客／上客、队列变化、关门离站。站牌、车辆、车门和人流共用活动状态；不得用两站直线连线代替驾驶路线。
- 地铁口：人流沿真实可用梯口／入口进出，与人行道和过街点相连；不制作的站内区域作为明确退出／生成边界。站口编号、楼层与运营条件单独核实，不能所有出口套同一通行模板。
- 生活：按街区加入卸货收货、外卖取餐、雪糕售卖、朋友聚会、清洁或观景等，人物、道具、车辆与空间声源同步；活动有开始、过程、结束，不永久重复单一动作。
- 声景与时间：视听使用一致的信号和活动状态；昼夜／晴雨影响照明与行为，不能只换滤镜。没有证据的日程标为设计编排，不冒充真实运营时刻表。

完成条件：本街段至少一组完整微活动可观察，交通设施确实运作；只摆站牌、停一辆巴士或放随机巡游者不算完成相应功能。

## 7. 用主角执行动线并打磨

1. 固定一条可重复路线及初始状态，实际控制白帽主角执行：主街双向走 → 转入纵深街巷 → 经过设施／人群 → 有开放高差时上下层 → 返回。路线不得只在无障碍空地里绕圈。
2. 在实际运行场景中检查脚底、碰撞、路缘、墙角、台阶／坡面、桥下遮挡、转角视野与景深；镜头区边界往返，确认输入不反向、镜头不反复跳变。检查暂停、区域切换及位置／楼层读档。
3. 原地观察至少两分钟，验证本次活动的开始与结束，公交靠站与站口人流不穿模、不堵死主角路线。按本次范围比较昼夜／天气预设；复杂活动未实现则明确列缺口。
4. 先跑编辑器，再导出本机可运行的独立 Player。记录机器、引擎／包版本、分辨率、可见角色／车辆、灯光、景深设置、帧时与内存；性能目标以当前策划案为准，禁止把编辑器观感称为独立 Player 结果。
5. 保存关键机位截图、必要的路线录像、运行日志和问题记录到 `docs/08-blocks/<block_id>/validation/`。有自动化能力就复用脚本／测试路线，但脚本文件存在或测试启动不算通过，必须检查实际返回与画面。
6. 按证据修复影响空间真实性、行走、遮挡和生活节奏的问题，重跑受影响路线；未涉及的检查无需全量重复。静态好看但无法自然走动时，优先修场景与镜头，不继续堆地标。
7. 工具、素材或硬件阻塞时保存当前成果、失败证据与可继续的下一步；不得声称已完成尚未执行的行走、截图、导出或性能验证。

## 8. 街区交付与版本记录

每个街区至少有：范围／路线说明、来源 manifest、逻辑骨架、街景参考索引、imagegen 提示词与概念图、资产清单、需要时的 Blender 源与导出、Unity 场景及依赖、验证记录和未解决项。资料／概念／生产资产／实机证据分别标识；分析用项目内 Markdown、独立 HTML 或标准图表。

每次收尾简要报告：完成内容、运行与视觉验证、未完成项、可点击文件路径、commit 与推送状态。概念验收和实机验收分开，用户未认可的画面不能记录为已通过主观美术验收。

所有文件修改完成并验证后，按根目录 [AGENTS.md](../../AGENTS.md) 的规则提交、推送并核对远程。
