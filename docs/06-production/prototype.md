# 首个 HD-2D 技术样板

研究基线：2026-11-01 / v0.4。按主题整理；建议与待验证项不等同于已实现功能。

本文是 [v0.1 实施规划](v0.1-implementation.md) 中 V1-02／03 的技术验证依据，不是完整首版的交付范围。旧样板尺寸只作候选，最终街段由 V1-01 核实站口、站位与真实通行后确定。

## 锁定方案前必须通过的小样

最新选段建议见 [弥敦道—海防道／A1 档案](../08-blocks/tst-nathan-haiphong/plan.md)，取代早期广东道街角优先方案。先做 20—30 米小样，再扩主街与支路，最终边界随人行连通性确定。无需一开始做完整海防道或把 Apple、站口、雪糕车强行放在一起。另设不计入真实地图的阶梯／天桥测试件。

生产顺序与交接物按 [HD-2D 制作 SOP](../../workflows/10-hd2d/hd2d-production-workflow.md) 执行。当前 URP 17.3 源码核查发现正交景深风险，因此先验证弱透视＋原生 DOF；正交比较需另列深度／景深验证，不作为等成本替换。详见 [镜头与渲染实施](../../workflows/10-hd2d/camera-lighting.md)。

| 验证项 | 通过条件 | 失败时如何处理 |
| --- | --- | --- |
| 空间与镜头 | 横向步行、深入支路、返回主街均能判断方向；双侧商铺有合理呈现；镜头区切换不反转输入 | 调角度／视距／切镜位置，再决定弱透视或正交 |
| 像素与深度 | 角色有清楚脚底、受光与稳定阴影；帽尖和树叶无明显深度毛边；移动纹理不持续闪烁 | 简化材质与后处理；先解决图像稳定再加细节 |
| 垂直通行 | 楼梯、坡面、桥下、桥上与停留层正确；读档恢复到同一层 | 修控制器、连接与碰撞，不靠渲染排序掩盖问题 |
| 框架省工 | 移动、暂停、镜头接入、场景切换可复用；新增代码集中在像素表现和街道逻辑 | 若需要重写控制器核心，重新评估框架与 Unreal 候选 |
| Agent 闭环 | 修改场景／材质／参数后可编译、运行、取得日志截图并导出 Mac Player | 记录缺失接口和人工步骤，不以 MCP 握手成功算完成 |
| 生活与性能 | 至少一组完整微活动；固定路线、固定分辨率与可见 NPC 数下测试白天／夜晚／景深开关 | 先限制阴影灯、透明层和远处更新；不直接扩大地图 |

技术样板不要求全城流式、完整商店室内或全城实时交通。只有这一街角达到主观美术要求、操作舒适和独立 Player 性能目标，才锁定角色像素尺寸、镜头参数、材质与模块规格。当前已建立 [环境验证工程](../04-engineering/local-development.md)，但街角样板尚未制作，付费框架尚未采购，也没有街区性能结论。
