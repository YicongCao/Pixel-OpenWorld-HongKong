# 项目远期 Roadmap

2026-11-01 · 产品路线规划 r1 · 状态：拟定，未开始游戏制作。

**先做一条值得步行和停留的香港街道，再把同样的质量扩展为相连街区，最终形成可持续扩充的九龙 HD-2D 步行世界。** 地图扩大与生活丰富必须一起推进，不以地标数量代替体验。

本文的 v0.1、v0.2 等是拟定的游戏版本；既有“策划 v0.4”是文档版本，不表示游戏已发布到 v0.4。首版具体任务见 [v0.1 实施规划](v0.1-implementation.md)。

## 起点与终点

已有可复用成果是：香港选区地图与行人／公共交通数据、来源记录、街区与生活目录、五张探索图、引擎复评、章节文档和 Git 工作流。它们尚未构成游戏工程、合格生产资产、已验证步行图或实机性能结论。

v1.0 的目标是经过验收的九龙步行路线网络：包含尖沙咀／尖东、西九及向佐敦—油麻地—旺角延伸的代表性街段；明确可走边界与连接，支持随时停留、往返、保存和继续。它不等于研究窗口内每栋建筑、每条巷子都已复刻。最终开放街段清单随生产测速和地图证据确定，不能把背景或未开放地区算成可探索面积。

主角、HD-2D 表现、真实街区关系和日常生活是持续约束。剧情、战斗、经济系统、联机、玩家驾驶／乘车不进入这份 Roadmap；之后若用户提出，再单独立项。

## 版本路线与完成门槛

| 版本／阶段 | 玩家能得到什么 | 地理范围与内容重点 | 必须建立的能力 | 进入下一阶段的门槛 |
| --- | --- | --- | --- | --- |
| 当前：研究基线 | 阅读资料与概念，尚不可玩 | 已有九龙选区与候选街角 | 数据可追溯、主题研究与执行流程 | 为 v0.1 核实选段、实景与技术环境，不把已有概念直接当资源 |
| v0.1：一条会生活的街道 | 白帽主角沿横向主街行走、转入纵深、观察活动、保存后继续 | 尖沙咀一个真实小街区；候选从广东道／海防道相关街段核实选择 | HD-2D 镜头与材质、3D 步行、公交靠站／站口人流、完整生活活动、独立 Mac Player | 首街段通过美术、动线、活动与性能验收；制作流程可重复运行 |
| v0.2：相连街区 | 自由往返 2–3 个相邻街段，方向与生活延续自然 | 从已通过街段向真实相邻区域延伸，形成至少一个可往返的短探索网络 | 区域切换、镜头区转换、保存恢复、共享模块和活动配置 | 第二街段能复用现有模块；单位街面制作成本下降，转场／读档不破坏空间与状态 |
| v0.3：尖沙咀核心漫游 | 从商业主街走向码头、海滨与尖东，感到不同空间节奏 | 广东道／海港城、天星码头、海滨、K11 MUSEA、尖东按连通性分批接入 | 商业、码头、海滨三类场景组合；区域声景与人流批次；在测试通过后引入有限城市时钟 | 每条开放连接逐段核实；不同区域能靠空间和生活辨认，而非只靠名称 UI |
| v0.4：西九连接 | 从密集商业街走向车站、文化场馆与开放广场 | 中港城—戏曲中心—西九龙高铁站等候选走廊；开放顺序按真实可走路径确定 | 大尺度地标的简化建模、场馆人流、开放空间表现及必要跨层连接 | 车站身份和通道层级正确；大地标不拖垮性能，街区切换不会像地图传送 |
| v0.5：九龙生活纵深 | 从尖沙咀北行，体验住宅、餐饮、市场与专门店差异 | 佐敦 → 油麻地 → 旺角，逐批制作；保留真实中间连接 | 市场／后勤／住宅模块、装卸收摊、休息日群体、雪糕售卖等有证据的活动组合 | 各区活动、资产和声音有区别；新增行为不导致队列死锁、存档错误或全城重复同一模板 |
| v0.6：城市时间与氛围整合 | 不同时段、天气与休息日形成不同的漫游体验 | 优先打磨已开放街区，不借此继续扩大地图 | 一致的时间状态、营业与活动切换、晴雨反应、光照／声景过渡和远近模拟层级 | 状态跨街区与读档一致；可走性和画面可读性稳定；每种预设均有独立性能证据 |
| v1.0：稳定漫游版 | 一张边界清楚、能长期自由往返的九龙街道网络 | 只发布已完成验收的街段目录；未开放区域明确提示 | 发布构建、设置、存档兼容、内容校验、缺陷回归和交付说明 | 无阻断性问题；完整路线实机验证；香港熟悉者反馈已处理；达到约定画面与性能标准 |

以上是内容和依赖顺序，不是一次性批量制作全部地标的任务列表。每个大版本内仍按 2–3 街段一批交付；一批未通过验收，不并行铺开下一大片区域。v0.4 西九和 v0.5 北向扩展可在 v0.3 通过后根据已验证资产复用成本调整先后。

## 持续推进的五条工作线

| 工作线 | 首版建立什么 | 后续如何扩展 | 持续记录什么 |
| --- | --- | --- | --- |
| 地理与取证 | 小选区、实际街景、正确路口／站位和引用关系 | 跨街段连通、分层通道、区域与年代差异 | 来源日期、覆盖缺口、设计压缩与证据状态 |
| 美术与空间 | 一套稳定镜头、白帽角色、受光像素材质及模块尺度 | 地标家族、街区材质差异、前后景与不同方向镜头区 | 实机对照、像素一致性、重复资产与手工修订 |
| 街道生活 | 有目的地行人、站口进出、公交靠站、一组完整微活动 | 社交群体、市场、码头、营业／天气活动差异 | 行为始末、路径占用、声音同步和玩家可通行性 |
| 运行与工具 | 一套控制器／镜头责任、Agent 修改到导出的完整过程 | 街区配置、资产校验、批量构建、必要时的预载 | 版本、失败原因、人工干预步骤和新增集成成本 |
| 验证与交付 | 固定动线、固定负载、截图／录像、独立 Player | 多区域状态与长路线、质量档位、版本回归 | 实测帧时、内存、视觉问题、发布 SHA 和未解决项 |

连续时间天气安排在后续整合，不代表首版可以没有灯光、声音和有始有终的活动。v0.1 就必须验证这些基础；后续增加的是持续变化、跨区域一致性和更多情境。

## 以什么决定扩大地图

每批街段登记以下指标，用于决定下一批规模；数字从实际制作开始累计，当前没有已测基线。

- **体验完整度**：真实路线能走、能返回、可停留；入口、站点与活动有合理空间关系。缺失一项就不是完成街段。
- **制作成本**：分别记录资料核对、贴图、建模、场景配置、活动适配、修复的有效工时；等待服务或用户审阅另计。
- **复用情况**：记录直接复用、参数变体和新增独有资产；比较同类、相近长度和密度的街段，不以大空地与复杂街角比较效率。
- **质量问题**：区分地理错误、像素／材质不统一、镜头迷向、通行错误和活动不同步；重复出现的问题先改规范或组件。
- **运行预算**：记录分辨率、可见 NPC／车辆、阴影灯、活动与区域数。性能恶化先定位成本，不自动通过删除全部人群来达标。

v0.2 完成后，只有第二街段比首段减少重复制作、且没有显著损失生活质量，才允许进入成片扩展。若主要工作仍是逐栋重新生成、手工纠错，优先修资产颗粒度和流程。

## 排期与资源的滚动方法

当前没有 Unity／框架／资产生产的完整实测，不能给整个九龙一个可信的固定完成日期。沿用已撤回的 8–17 人日估计也不合适；这份 Roadmap 采用完成门槛驱动排期。

1. v0.1 先执行“选段取证＋环境闭环＋灰盒镜头”三个任务包，得到地图复杂度、可用组件、实际导出路径和基本画面成本。
2. 以首栋商铺／首组人物动画／首个活动的实际工时，估算剩余资产与场景工作，并单列集成和修复，不用生成图片张数代替完成工作量。
3. v0.2 再用第二街段的数据更新每类街段的区间估算；此后每批排期只覆盖下一批确定范围，不预先承诺所有远期街区日期。
4. 当前资源假设为用户负责方向与主观画面验收，Agent 负责取证整理、编码、自动化和可执行验证；像素修订／模型调整是否需要人工参与，以样板质量决定，不假设能够全自动达到目标。

需要购买的框架、素材、服务或发布成本，在明确商品和预算后单独处理；这份规划不等于采购、引擎迁移或公开发布游戏的授权。已有文件修改后的 commit／push 授权继续有效。

## 风险与调整路径

| 触发情况 | 优先处理 | 对 Roadmap 的影响 |
| --- | --- | --- |
| 小区域无法同时满足真实站口／站位与纵深空间 | 重新选段或纳入有真实连接的必要短段，列明新增资产成本 | 在 v0.1 选段阶段解决，不后期搬动设施拼图 |
| 镜头与像素质感反复不成立 | 冻结新增资产，调整俯角、像素密度、透明深度与前景遮挡 | 延后扩区，保持已验证的地理资料 |
| 候选框架需重写核心控制器或 Agent 无法稳定诊断 | 先记录阻碍，比较兼容组件；必要时仅用同一街角评估 Unreal | 技术路线重新评估，不同时维护多个完整游戏版本 |
| 新街段大量返工、复用收益不明显 | 缩小同批规模，改模块与活动配置方式 | 维持 v0.2 的复用阶段，暂缓成片地图 |
| 群体／交通活动压低帧率或堵塞道路 | 先优化远处更新、占用管理、阴影与透明层 | 保留近处可观察的完整活动，再重新测负载 |
| 真实地理、营业或现场情况与旧快照冲突 | 记录年代、更新对应证据与设计，不静默覆盖旧来源 | 对受影响街段回归，不推翻无关区域 |

v1.0 之后，可以评估更精细的支路、更多公共空间、室内片段或港岛远景之外的新地区。它们属于候选方向；剧情、乘车与大范围城市模拟仍不自动加入。
