资产生产与复用

研究基线：2026-11-01 / v0.4。按主题整理；建议与待验证项不等同于已实现功能。

资产生产：让第二个街段更便宜

旧版静态样板预算仅作内容量参考，需按新镜头重估：1 个地面图集、6 个普通立面模块、3 类品牌招牌 / 橱窗模块、12 类街道道具、1 名主角的四向动作研究、1 辆出租车和 1 辆巴士、4 种路人配色变体。这只是静态起步预算，不是终极内容上限；人群需要追加站立、坐下、等候、携物、推车等动作，不能靠四种配色替代行为差异。按首街段选定的活动增加站口/站牌、货车/手推车、箱筐和声音等成套资产，再实测制作成本。

普通资产包括交通设施、道路家具、大楼/商铺界面、后勤设备、停留设施、气候设备、保洁维护、市场货品、海滨和酒店界面等 15 个资产族。完整目录与 16 类活动见 街道生活设计。模块复用同时保留街区和年代差异。

建筑生产资产拆为具有体积的底座、立面、转角、屋顶／雨篷，配独立像素贴图、招牌与发光遮罩；共享世界尺寸与基准点。法线与阴影代理按效果需要制作，真实几何承担基本深度。先验收一栋商铺的分层包，再批量生产。

生成式工具用于概念、色调和局部方案探索。进入生产需要像素编辑、统一调色板、模块建模与 UV、足底锚点、深度／阴影检查和遮挡分件。不要把整幅 AI 街景按屏幕平铺：这样会失去转角、碰撞、通行与邻接一致性。

生成输出与手工修订分别放 generated/ 和 authored/；构建脚本只刷新 generated。已精修图块通过清单选择，重跑脚本不能覆盖 authored。这个约定直接针对旧项目程序化生成覆盖手工精修的风险。

首街段通过后，用同一套素材做第二条相邻街段。若主要时间仍用于逐栋重画、几乎没有模块复用，就暂停扩区，先修改资产颗粒度与镜头。此时新增更多自动化工具通常不能解决问题。

执行工作流

完整采集、真实街景图生图、贴图、按需 Blender 建模及 Unity 导入步骤由根目录 agent.md 维护；本章记录制作建议，不复制一份易分叉的执行规则。

实施阶段与验收

以下是工作量估算，用于约束范围，不是 Agent 完成时长承诺；没有以当前素材做过生产测速。按一名熟悉引擎的制作人员、有像素美术修订参与估计，实际耗时主要取决于美术接受与街段资料质量。

阶段内容工作量初估通过条件
P0 本轮源数据提取、概念图、引擎调研、策划案已完成本轮文档交付数据可复现；概念图明确标注边界
P1 框架与渲染验证横向街角＋纵深支路＋高差测试件、3D 框架接入、Agent 闭环、日夜与真实景深框架/渲染组合实测后估算移动稳定、组件可复用、Agent 可运行诊断；分层灯光与遮挡成立
P2 首个生活街段真实商铺/设施关系、统一像素资产、至少一组完整微活动与停留行为待 P1 活动样板实测后重估可走可停，能观察活动始末；空间、声音和动作一致
P3 相邻街段第二段、模块复用、镜头区／区域切换与保存待 HD-2D 样板测速后重估可往返、读档正确；淡入淡出可接受，复用降低新增制作量
P4 尖沙咀核心向海港城 / 海滨 / K11 与西九龙方向分批扩展在 P3 后按街段实测重估每批 2–3 街段验收后再扩大，不提前承诺整片九龙工期
P5 北向扩展佐敦—油麻地—旺角未估算核心区的稳定性、密度和美术标准已成立

建议首个里程碑仍是 P1–P3；此前纯 2D 的相邻街段 3–6 人日估计也不沿用。此前 8–17 人日 的总估算随框架/渲染验证范围变化而撤回，完成 P1 后重估，不承诺一次完成整个开放世界。若连续两次美术复核仍不能接受同一镜头，先修改镜头或像素密度，不继续添地标。

下一步具体工作单

首选广东道—海防道附近的真实街角，先核对双侧沿街立面、人行过街与连接位置；确认参考年代和地标街侧，再做可往返的灰盒。比较弱透视／正交镜头、横向步行与纵深支路可读性；用独立高差测试件检查楼梯、桥上桥下和保存恢复，不为技术展示修改真实街网。

随后接入白帽像素人物、一栋分件商铺和一组有依据的街道活动，测试白天／夜晚／景深开关、角色受光与遮挡，并完成 Agent 改场景—编译—运行诊断—导出闭环。框架与渲染结果成立后，才锁定像素尺寸、模块规格和正式版本。

这一步验证：街道层叠是否像香港、走入纵深是否自然、停下来是否有生活可看、组件与 Agent 工作流是否省工、第二条街是否能沿用生产方式。 当前地图、五张探索图与文档为研究交付；尚未得到用户美术验收、可玩版本或性能结论。

首个 HD-2D 街角样板

研究基线：2026-11-01 / v0.4。按主题整理；建议与待验证项不等同于已实现功能。

锁定方案前必须通过的小样

首个样板改为广东道—海防道交界附近的一个可核实街角：约 80–150 米主街界面＋约 30–60 米纵深连接作为选段范围，最终边界随人行连通性确定。无需一开始做完整海防道或把 Apple、站口、雪糕车强行放在一起。另设不计入真实地图的阶梯／天桥测试件。

验证项通过条件失败时如何处理
空间与镜头横向步行、深入支路、返回主街均能判断方向；双侧商铺有合理呈现；镜头区切换不反转输入调角度／视距／切镜位置，再决定弱透视或正交
像素与深度角色有清楚脚底、受光与稳定阴影；帽尖和树叶无明显深度毛边；移动纹理不持续闪烁简化材质与后处理；先解决图像稳定再加细节
垂直通行楼梯、坡面、桥下、桥上与停留层正确；读档恢复到同一层修控制器、连接与碰撞，不靠渲染排序掩盖问题
框架省工移动、暂停、镜头接入、场景切换可复用；新增代码集中在像素表现和街道逻辑若需要重写控制器核心，重新评估框架与 Unreal 候选
Agent 闭环修改场景／材质／参数后可编译、运行、取得日志截图并导出 Mac Player记录缺失接口和人工步骤，不以 MCP 握手成功算完成
生活与性能至少一组完整微活动；固定路线、固定分辨率与可见 NPC 数下测试白天／夜晚／景深开关先限制阴影灯、透明层和远处更新；不直接扩大地图

P1 不要求全城流式、完整商店室内或全城实时交通。只有这一街角达到主观美术要求、操作舒适和独立 Player 性能目标，才锁定角色像素尺寸、镜头参数、材质与模块规格。当前完成的是研究、地图对照与概念图，尚未建立游戏工程、购买框架或测得性能。
