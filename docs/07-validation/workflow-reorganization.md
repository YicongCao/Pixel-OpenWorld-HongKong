## 需求与采用流程

用户要求把执行方法从 docs 拆到 workflows，按总流程、HD-2D 子流程、资产流程分类；强调方法第一优先，实施先选流程，反馈回写流程并复验。本批主流程为 WF-MAINTAIN 1.0，执行范围是研究／文档迁移；没有运行 Unity 或重做资产。

## 交付与方法改进

- 从 docs 迁移总流程、HD-2D SOP、镜头光照、角色生产四篇；抽出建筑模块制作和根入口的迭代省量约定，新建景物、场景装配、反馈维护流程，共 9 个 ID。
- AGENTS 维护强制路由与反馈闭环，README 明确工作流价值；docs 保留静态资料、计划与证据。使用 [工作流目录](../../workflows/README.md) 单点路由，避免根入口重复全文步骤。
- 工作流合同统一为输入、步骤、输出、验收与回退，记录版本和执行范围；局部修改复用已有阶段证据，不强制重跑全链。收到反馈自动定位对应步骤，修改方法与产物，再同条件复验；未验过的方法标明状态。
- 原访谈启发落入镜头／可见目标、角色环境联合小样、受约束视角、时段活动配套和小步预览；详细来源见 [访谈研究](../03-hd2d/octopath2-interview-lessons.md)，没有冒称原作公开了完整资产／烘焙管线。
- 用户反馈“路牌／站牌粗糙、景物目录不完整”落为 WF-PROPS B/C 的原物取证、版式／字体依据、安装结构和实机辨识检查；[广东道盘点](../08-blocks/tst-canton-demo/scene-inventory.md) 如实保留占位状态，尚未精修这些资产。
- “完成模型之后还缺什么”落为 WF-SCENE：地面通行、建筑／景物摆放、活动空间、无效果试走、人车与声景、试烘／最终烘焙、Player 回归和交付。总流程调用它；不是第二套相互竞争的街区总流程。

## 证据与保护边界

盘点读取当前序列化场景、五个制作脚本、既有 AppleBay 验证记录；未以脚本存在等同新测试通过。原始数据、概念与历史验证 JSON 保持原样；[迁移映射](workflow-migration.json) 保存旧路径、目标路径和迁移前哈希，目标 workflow 是继续维护的文本，不承诺字节不变。

本批跳过游戏构建／行走／烘焙，原因是没有修改游戏代码或资产。路牌字体／准确色值未取得目标牌型证据，记录为后续取证项。文档迁移、引用和历史数据校验与画面改善验收分开。
