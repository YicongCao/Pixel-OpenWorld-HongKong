# Codex 研究阅读与维护约定

本文件由根目录 `AGENTS.md` 显式引用，与 [街区还原工作流](../workflows/00-project/街区还原工作流.md) 配合使用。它负责资料阅读与归档，不另设一套制作或发布授权。

docs 只维护事实、研究、计划、清单与证据；实施的动词和门槛在 [workflows](../workflows/README.md)。不要在资料页新增另一套可执行 SOP。

## 阅读顺序

1. 先读 [总目录](README.md)，确认研究范围、各主题位置及当前“未实机验证”的状态。
2. 首次接触项目读 [项目总纲](01-vision/vision.md)；之后按 [Skill.md](Skill.md) 只读取当前任务需要的主题和来源。
3. 回答或实现前区分：用户已确定目标、研究建议、地图／照片证据、概念探索、已执行测试、待验证缺口。不要把其中一种写成另一种。
4. 制作角色／环境／镜头时先读 [HD-2D 生产 SOP](../workflows/10-hd2d/hd2d-production-workflow.md)，按需读角色与渲染细则，并核对专业资料／项目试作参数的区别。
5. 制作街区时按 workflows/00-project 的街区总流程执行，补充阅读 [街区归档规则](08-blocks/README.md)，将范围与实际进度写入对应街区档案。

## 内容归属

- 01：产品目标和首版边界；不堆具体引擎 API、地图统计或图片画廊。
- 02：真实地理、交通与来源；不把设计压缩或 NPC 日程反写为地图事实。
- 03：镜头、空间表达、像素美术及概念；概念不是已验收游戏资产。
- 04：技术选型、组件、Agent 集成、渲染与运行架构；版本兼容和性能必须独立验证。
- 05：普通设施、活动、人群、声景、时间天气；地标定位引用 02，具体渲染实现引用 04。
- 06：生产研究、专业来源、预算、Roadmap 与实施计划；不重复维护引擎比较与地图清单。
- 07：验收要求与证据记录；历史 JSON 原样保留，新测试另存，未做测试明确写未执行。
- 08：具体街区的范围、证据、进度、资产清单与实机结果；普适结论回写其所属主题。

## 编辑与检查

- `docs` 根目录只保留 `README.md`、`Agent.md`、`Skill.md` 三个入口文件；新增研究归入主题子目录。
- Markdown 为事实与建议的维护源；HTML 是生成视图。同一结论在所属主题维护，其他章节以链接和短摘要引用，不重新生成混合巨型长页。
- 图件放在所属主题 `figures/`；原始数据、参考原件与生产资产继续按街区还原工作流归档。保留来源、时间、哈希和坐标约束。
- 移动文件时同步更新 Markdown、根目录指引、脚本输出路径、派生 manifest 和章节清单；历史日志中的原路径／原哈希保留，另写迁移映射。
- 文档变更执行 [WF-MAINTAIN](../workflows/00-project/workflow-maintenance.md) 的文档维护分支；来源在本目录单点维护，步骤在 workflows 单点维护，交叉引用即可。
- 完成并验证每批改动后，按根约定 commit、push 并核对远程；不得将仅本地修改写成已同步。
