# 渲染与运行架构

研究基线：2026-11-01 / v0.4。按主题整理；建议与待验证项不等同于已实现功能。

## 渲染与通行的具体方案

**主选验证栈：Unity 6 + URP Universal Renderer（3D 路径）＋受光像素角色平面＋3D 街道几何与碰撞＋Cinemachine 镜头区。** 不以 URP 2D Renderer、全局 Y-sort 或 2D 物理为基线。完整版候选比较见 [引擎复评](engine-selection.md)。

### 深度、遮挡与图层

人物逻辑根节点负责 3D 移动、碰撞与足底位置；视觉子节点是直立的角色平面，只绕竖轴朝向镜头，避免连脚底一起倾斜悬空。先验证 alpha clipping 的受光材质及正确深度／投影通道；透明玻璃、粒子与半透明淡出单独测试，不假设它们和不透明几何拥有完全相同的景深行为。[URP Lit 材质](https://docs.unity3d.com/6000.0/Documentation/Manual/urp/lit-shader.html)

真实几何深度处理正常前后遮挡；近景屋檐、树冠和立面设置可选择的遮挡区域，仅在妨碍玩家阅读时淡出或抖动裁切。墙体背后的主角不应永久透墙显示。雨棚、屋顶、招牌、灯具与楼体分件，有自己的碰撞／阴影策略；活动楼层与渲染层并不是同一个字段。

角色投影须额外检验：面片旋转时不能让阴影剧烈跳动；必要时用独立简化投影代理或稳定接触阴影。模型／贴图法线是否值得制作，以夜间侧光样板决定；不是给每个路牌强制做全套 PBR。

### 光照与景深

路灯和橱窗的实际灯光负责照亮路面、白帽和人物；发光贴图负责招牌自身亮度，bloom 只提供光晕，三者分别调试。静态环境可比较烘焙光照／光照探针与有限动态灯；记录日夜切换时的兼容方式，避免仅改变太阳却保留明显错误的静态夜景阴影。不把光追、实时全局光照或体积雾列为 HD-2D 成立的先决条件。

URP 景深先验证深度输入，再平滑追随主角附近稳定目标的相机前向深度；可走区、重要标识和 UI 保持可辨。Gaussian 只能做远景虚化，树叶／雨篷等前景也要虚化时验证 Bokeh。本地 URP 17.3 的 DOF 深度转换存在正交限制，优先弱透视样板；这项源码判断尚非实机结果。透明边缘、白帽漏色、焦点抖动与性能分别检查，并提供关闭景深选项。具体步骤和证据见 [HD-2D 镜头与渲染实施](hd2d-camera-lighting.md)。[Unity 6.3 官方模式说明](https://docs.unity.com/en-us/engine/6000.3/manual/post-processing-and-full-screen-effects/urp/effect-list/depth-of-field-urp/volume-override)

### 坐标与移动

地理空间继续保留原坐标；游戏布局另存：`game_x = east`、`game_z = north`、`game_y = elevation`，初始采用 1 Unity 单位对应 1 个设计米。HKPD 高程先扣除明确记录的本地高程基准，再映射；若艺术压缩发生，写独立转换记录，不改源数据。右侧示意图的 0.55 压缩不作为默认世界缩放。

输入根据相机的地面投影变换为世界移动；镜头过渡期间需锁定或平滑插值输入基底，避免按住右键时突然折返。转场触发器有进入／退出余量，防止在边界反复切镜。楼梯和坡面使用 3D 控制器的坡度／台阶参数；人行导航使用分层可行走面及明确跨层连接，避免 NPC 穿楼或把桥上桥下当同一路面。

Cinemachine 提供镜头间自定义过渡，但街段触发、输入连续性、遮挡与聚焦属于本项目适配责任；还需确认框架所用 Cinemachine 主版本。[官方镜头过渡](https://docs.unity3d.com/Packages/com.unity.cinemachine@3.1/manual/CinemachineBlending.html)

## 最小技术结构

离线加工链：`真实 GIS → 选段与证据核对 → 独立游戏布局 → 模块化 3D 场景＋像素资产 → 引擎场景`。运行时只读加工后的资源，不联网查询 GIS，不依赖旧仓库，也不加载全港 GPKG。

先复用框架与引擎已有组件，再写香港街道需要的适配：

- 运动与输入：采用一个 3D 控制器，移动根节点与像素视觉子节点分开；验证坡面、台阶及相机相对输入，避免并行控制器争抢位置。
- 镜头：Cinemachine 或框架兼容的相机负责跟随与过渡；项目配置街段镜头区、切换余量、焦点和遮挡处理，转场期间输入不能突然反向。
- 区域：首街角常驻；相邻街段先允许短淡入淡出，是否预载／流式由实测决定。按沿街场景和连接口分区，不以旧 64×64 瓦片强制分块。
- 资产：路面、体积立面、雨棚／屋顶、橱窗与灯具分件；角色以 alpha-clipped 受光平面为起点，检查深度、阴影和半透明边缘。
- 楼层与导航：3D 碰撞、可行走面和明确跨层连接；桥上桥下独立，投影相交不建连接。人群路径必须遵守路口、队列和活动占用。
- 状态：复用可用的保存设施，项目定义区域、世界位置、朝向、楼层、活动时间、设置和版本；框架库存存档不是完整世界存档。
- 街道活动：把人物、车辆、道具、服务门、等候锚点与空间声源绑定成活动；近处完整模拟，远处简化，合理进出场。

保留 `source_id`（不可变来源）、`place_id`（现实地点）、`asset_id`（复用资产）、`instance_id`（本次放置）四种身份。世界资产字段候选为 `chunk_id、level_id、position_m_xyz、foot_anchor_local、collision_shape_3d、occlusion_group、camera_zone_id、source_ids、geographic_edit_note`。真实高程与游戏高度转换显式记录，玩法楼层、渲染深度、光照分组不能混用。

资源读取、实例化、碰撞创建和首次着色器使用需要分别测量。加法加载支持不等于已解决城市流式；首版不需要 ECS、服务端或全城人口常驻模拟。深度、光照和景深见本篇上方；像素资产规范见 [HD-2D 美术](../03-hd2d/art-direction.md)。
