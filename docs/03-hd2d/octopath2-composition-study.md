# 从《八方旅人 II》画面反查香港样板

2026-11-01 · 实际查看官方画面、重看本项目旧概念、在同一 Unity 场景比较镜头。本文区分开发者陈述、图像观察和本项目方案；没有从截图反推出官方精确 FOV、俯角或内部资产做法。

## 得到的制作原则

**先把可探索世界组织成一个方向关系稳定、可前后穿行的画面，再为这组视角制作资产。** 对本项目来说，左右沿主要街面移动，上下进出纵深连接，真实的高度仍由碰撞／台阶处理；人物使用与这些方向一致的像素转面。镜头中的店面、路缘和人物共享这套关系，深度由近景遮挡、中景活动、后方立面与通道共同表达。

它不等于只有左右的横版游戏，不等于任意 45° 等距视角，也不等于整张背景加模糊。官方访谈指出探索采用固定镜头、背景几乎全为 3D；战斗和事件会使用更大幅度的镜头旋转。我们采用受约束的探索镜头来控制制作范围，这是本项目策略，不能冒称原作所有建筑背面都没建。[Acquire／Square Enix 开发者访谈，2023-08-22](https://www.unrealengine.com/developer-interviews/octopath-traveler-ii-builds-a-bigger-bolder-world-in-its-stunning-hd-2d-style?lang=en-US)

## 原来的问题在哪里

重看 [第一张广东道概念](../../assets/concepts/01-canton-road-day.png) 与原 [提示词](../../assets/concepts/prompts.json)：它已有横向商业界面和巷口，但提示词要求传统俯视正交、排除 3D 渲染及景深，同时混排未经核实的 Apple／7-Eleven／麦当劳。它能提供内容密度与色彩，不能继续作为空间生产合同。

[第二张维港图](../../assets/concepts/02-victoria-harbour-vista.png) 是面向海面的观景插画，适合作为特定观察点的情绪参考。它没有定义日常行走带宽度、转弯时的可见面、相机跟随和角色方向，不能直接延伸成整片可探索香港。它有远近关系，问题并不是“完全没有透视”，而是没有把透视与可操作空间连接起来。

本项目第一版实机又出现了另一个问题：为了多看建筑侧面，将相机 Y 朝向设为 −110°。主要人行路线大致向北偏西，镜头右方向却偏向东；按 D 会逐渐靠向路边。侧向动画、道路和输入不一致，容易产生斜着擦墙走的感觉。大量前景沥青、均匀重复的纹理和未完成的背景体块，使画面更像建筑展示。仅放大人物或增加 DOF 无法解决这些问题。

## 本轮实际调整

保留米制 GIS、真实街侧和原路线，在副本 `NathanHD2DStudy.unity` 进行比较，旧 `NathanArtSample.unity` 保留为历史基线。三组镜头使用相同角色与几何，不通过移动建筑伪造改善：

- A：原斜向，28° 俯角、Y=−110°、32° FOV、34 米距离。
- B：沿主街校正，25° 俯角、Y=−95°、32° FOV、34 米距离。
- C：沿主街的弱透视，25° 俯角、Y=−95°、20° FOV、55 米距离。

C 的相机更远，但目标处竖向视野仍约 19.4 米，接近此前 34 米／32° 的 19.5 米，**没有撤销用户希望突出主角的选择**。投影收敛更弱，沿街立面和人物活动带更稳定；仍然是透视相机，保留深度／遮挡／URP 景深。参数是项目试验，不是从原作抄出的相机值。

输入现在可绑定固定的街区轴，而不跟随相机瞬时右方向旋转：屏幕左右对应沿街方向，纵深方向与之正交。白帽始终用面向镜头的视觉面片，按同一输入参考轴选择前后左右帧；逻辑朝向不直接旋转面片侧身成纸片。允许斜走，保持方向切换迟滞，停步回到站姿。没有把玩家绑到只能左右走的轨道。

弱透视远镜头使原 50 米阴影距离不够，A1 阴影会消失；本轮将 PC URP 阴影距离调为 90 米，再比较同等照明的镜头。长焦并非无成本，还要检查阴影精度、像素采样和景深参数，不能把这类渲染变化误当美术收益。

## 怎样具体减少制作工作量

以下是从受约束视角推导出的本项目方法，不是对原作内部模型的断言。

1. **先画可见面清单，再做建筑。** 取整条可走路线、允许的相机范围及全部昼夜机位的可见集合，不只看出生点截图。沿街建筑优先做正立面、会露出的侧面回折、雨篷及屋顶边缘；不进入也不被看见的室内和背面暂不精做。背面若参与投影／反射，保留低复杂度代理；阴影、玻璃反射和未来切镜均可能扩大范围。
2. **按空间职责选资源形式。** 可绕行转角、台阶、入口、栏杆及近处车辆保留真实 3D 深度；固定视角的远处窗格、空调、小装饰可合并进立面纹理／浅层模块；不可达远景可用卡片或低面数轮廓。卡片不得承担玩家可穿行的巷道或可绕行建筑，不能把所有树都用一张正面图顶替。
3. **立面做模块，辨识元素做例外。** 复用窗跨、楼层带、墙面材质和门店宽度；独立替换店招、橱窗内容、檐口和真实商业标识。需要轮廓／接触阴影的突出物才做几何；不逐个建模每块砖或每片树叶。
4. **人物先做少量可靠方向。** 同一像素角色复用站姿与步行图集，先保证四向在当前镜头下成立；斜向和活动确有需求时再补帧。NPC 的目标、路径和状态独立于外观，不能为省动画把所有人变成只会左右摆动的贴纸。
5. **通过镜头区扩展，而不是允许任意旋转。** 海防道在本区保持纵深；未来要把另一条主街横向展示，建立有明确转场的独立镜头区并重新列可见面。跨区期间冻结输入参考或平滑换轴，验证持续按键不会突然反向。首街区本轮没有实现多镜头区切换。
6. **把精修集中在行走焦点带。** 先确保脚底、路口、站口、店招与生活活动可读，再细化中远景。前景遮挡用于建立空间层次，但不长期盖住主角；景深只做最后分层，不掩盖破洞、错误高差和缺失模型。

这减少的是“必须被完整制作并验证的可见面、动作方向和独有资产种类”，没有测得统一节省百分比。现有粗糙模型不会仅靠改相机自动变成《八方旅人 II》品质；仍需要重新处理 A1 尺度、道路接缝、植被轮廓、材质像素密度和生活密度。

## 街道两侧与纵深支路的制作取舍

2026-11-01 补充：用户从实机发现固定探索镜头主要展示一侧街面。以下为基于该约束的本项目生产策略，不是“HD-2D 只能显示一侧”的引擎限制，也不是原作所有建筑均未制作背面的证据。开发者确认探索使用固定镜头、背景几乎全为 3D，而事件和战斗可旋转镜头；据此能推导有限视角的省量机会，不能推导原作实际省掉了哪些网格。[开发者访谈](https://www.unrealengine.com/developer-interviews/octopath-traveler-ii-builds-a-bigger-bolder-world-in-its-stunning-hd-2d-style?lang=en-US)

**街道两侧不必投入相同的立面制作量。** 镜头正对侧承担店面、商标、入口、橱窗与生活活动的主要展示；靠镜头侧可只制作会进入画幅的檐口、屋顶边缘、墙体局部、树冠、栏杆等前景。具体露出哪一面取决于相机与建筑的真实关系，不统一假设是背墙。不进入且不可见的内部／背面可以暂不精做，但碰撞、阴影、反射仍需的几何保留简化代理。遮挡玩家的前景需要裁切、隐藏或其他明确方案，不能靠加大模糊解决。

**这会影响探索体验：过街本身不会让相机转向。** 保持当前朝向时，海港城一侧的重要店面可能长期无法正面展示。若它们也是体验重点，应先为该侧规划独立镜头区和清楚的转场，再列该区的可见面；不要把商铺搬到错误街侧，也不要为了展示一切临时开放任意旋转。新镜头区会增加制作范围，需验证输入轴、角色转面、连续按键及返回时的方向一致性。当前项目尚未实现这些转场。

**海防道的“侧视”是镜头关系，不是建筑分类。** 垂直于广东道的连接街，在当前机位向纵深延伸；两侧真正朝向海防道的店面会呈斜侧视，甚至接近侧向压缩。不能将它们全部替换成没有门窗的山墙。精修集中在转角、入口凹槽、雨篷、垂直招牌、必要窗跨和台阶；重复区域可用模块或浅层立面。玩家深入、返回或侧移时露出的面必须纳入范围，近处可绕行转角仍有体积。远处不可达区域才适合受限背景卡。

扩产前为每栋建筑／街铺建立以下五类清单，可按同一构件承担多种职责记录：

1. **主要展示面**：独有店招、入口、陈列与材质，优先精修。
2. **转角可见面**：必要侧返、门洞、雨篷厚度与可见窗跨，保留体积。
3. **前景遮挡面**：只做实际可见轮廓与细节，同时验证主角可读性。
4. **仅投影／反射代理面**：使用最低必要复杂度；若反射中清晰可见，就升级为可见资产，不能仍按纯轮廓处理。
5. **无需制作面**：全部允许机位均看不到、不影响通行／遮挡／光照／反射的部分，明确暂不制作。

每条关联 `building_id / asset_id`、`camera_zone`、路线检查点、面朝向、可见依据、资产形式、碰撞／投影／反射职责和待验证项。取整条路线及全部允许镜头的可见并集，不只检查起点；镜头、通行边界、昼夜灯位或反射方案改变时重新审查。清单放各街区档案，不能反写 GIS 或把美术省略解释为现实中没有建筑。

当前广东道优先把 Apple／莎莎所在展示侧做完整模块；靠镜头侧按实际可见前景与代理需求制作，海防道先验证纵深入口和转角。省掉的主要是不可见面的独有纹理、精细几何与验证工序；没有测得节省百分比，也不据此降低人物、标识、可走空间和生活活动的质量。

## 后续 imagegen 的约束

制作输入还需包含上节的逐栋可见面清单；不能让概念图为展示两侧店招而擅自翻转建筑或改变街侧。

先用已验证的灰盒截图固定画面主轴、机位、人物屏幕高度与路口位置，再输入实景参考。提示词分清“概念渲染”与“资产纹理”：概念应体现固定探索视角、弱透视、横向活动带、纵深连接、前中远层与可读角色；纹理图集才要求正交平铺、无投影、无烘焙光照。不能再用“不要 3D、不要光照、不要景深”的纯 2D 条件约束 HD-2D 场景图。

概念中明确可走区域、禁止搬移的设施和用途；每张图检查角色前后左右是否能在同一机位成立。生成图只指导风格，尺度、碰撞和地理仍来自数据／实机。原两张图保留为历史，不覆盖文件或修改其来源哈希来假装最初已符合新规范。
